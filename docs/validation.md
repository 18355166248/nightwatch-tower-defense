# 《夜城防线》验证记录

> 状态只使用：未开始 / 进行中 / 通过 / 失败 / 无法验证。

## 1. 基本信息

- 游戏名：夜城防线（Nightwatch Tower Defense）
- 类型与核心循环：自由摆塔改变路线，以路径增益配合火力守住出口
- 目标平台：竖屏移动端 H5
- 引擎与版本：Cocos Creator 3.8.8 + TypeScript
- 目标方向：竖屏
- 性能底线设备：iPhone 12 Safari / Redmi Note 11 Chrome
- 目标帧率：60 FPS，底线 P95 帧时间 ≤33.3 ms
- 首屏预算：纹理传输体积 ≤3 MiB
- 整包预算：构建产物传输体积 ≤20 MiB

## 2. 方案否决风险

| 风险 | 为什么可能推翻方案 | POC 场景与最终量级 | 指标 | 状态 | 证据 |
|---|---|---|---|---|---|
| 竖屏网格误触 | 自由摆塔若落格不稳定，核心操作不成立 | 右侧浏览器三网格的拖拽/点击/非法/撤销 | 功能与状态原子性通过 | 通过 | `docs/poc/phase-a-browser-regression.md`；真机数据延后至发布前 |
| 活敌改路回头或卡死 | 战斗中建塔可能破坏路线状态 | 100 次承诺格/回头/等长路回放 | 0 回头、0 卡死、0 状态分叉 | 通过 | `docs/poc/phase-a-path-replay.jsonl`、`phase-a-automated-results.json` |
| 迷宫没有实战收益 | 路变长但没有决策价值会推翻核心卖点 | 120/450 金币等预算成对 fixture | Phase A 路径门槛；Phase B 再测时间与漏怪 | 通过 | 三网格短折线 +4，长蛇形 ≥80%；`docs/poc/phase-a-report.md` |

结论：自动化 POC 与右侧浏览器工程门禁通过，允许继续第一关 Phase B 灰盒。首次玩家评审待收集；真机只是延后，不是通过。

## 3. 单局竖切

## 5. Phase A 当前结论

- 已验证：三种网格短折线均增加 4 格，长蛇形均增加至少 80%；14 条规则测试与 100 次动态改路回放通过。
- 已验证：Cocos Web Mobile 发布构建、右侧浏览器点击/拖拽/非法拦截/撤销/运行中改路；控制台 0 error / 0 warning。
- 未验证：首次玩家理解，首屏/整包网络压缩体积；真机触控与帧时间改为发布前补测。
- 修复项：按钮可读性与发布构建统计遮挡均已复验关闭。
- 阻断项：Phase A 工程阻断已清零；可进入第一关灰盒，不得跳过后续首次玩家决策与发布验收。

## 6. Phase B 当前结论

- 已验证：第一波 8 敌人生成、路径运动、稳定索敌、伤害、击杀奖励、暂停冻结、恢复和胜利结算。
- 已验证：空场开战被“两座塔”门禁拒绝；短折线 fixture 满足 4 塔、路径 +4 后允许开战。
- 已验证：Cocos Web Mobile 发布构建通过，右侧浏览器控制台 0 error / 0 warning。
- 未验证：玩家首次理解、漏怪的浏览器实战场景、后续波次、正式数值、音画反馈与发布性能。
