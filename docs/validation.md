# 《夜城防线》验证记录

> 状态只使用：未开始 / 进行中 / 通过 / 失败 / 无法验证。

## 1. 基本信息

- 游戏名：夜城防线（Nightwatch Tower Defense）
- 类型与核心循环：自由摆塔改变路线，以路径增益配合火力守住出口
- 目标平台：竖屏移动端 H5
- 引擎与版本：Cocos Creator 3.8.8 + TypeScript
- 目标方向：竖屏
- 性能底线设备：iPhone 12 Safari / Redmi Note 11 Chrome
- 目标帧率：60 FPS，底线 P95 帧时间 ≤33.3 ms
- 首屏预算：纹理传输体积 ≤3 MiB
- 整包预算：构建产物传输体积 ≤20 MiB

## 2. 方案否决风险

| 风险 | 为什么可能推翻方案 | POC 场景与最终量级 | 指标 | 状态 | 证据 |
|---|---|---|---|---|---|
| 竖屏网格误触 | 自由摆塔若落格不稳定，核心操作不成立 | 右侧浏览器三网格的拖拽/点击/非法/撤销 | 功能与状态原子性通过 | 通过 | `docs/poc/phase-a-browser-regression.md`；真机数据延后至发布前 |
| 活敌改路回头或卡死 | 战斗中建塔可能破坏路线状态 | 100 次承诺格/回头/等长路回放 | 0 回头、0 卡死、0 状态分叉 | 通过 | `docs/poc/phase-a-path-replay.jsonl`、`phase-a-automated-results.json` |
| 迷宫没有实战收益 | 路变长但没有决策价值会推翻核心卖点 | 120/450 金币等预算成对 fixture | Phase A 路径门槛；Phase B 再测时间与漏怪 | 通过 | 三网格短折线 +4，长蛇形 ≥80%；`docs/poc/phase-a-report.md` |

结论：自动化 POC 与右侧浏览器工程门禁通过，允许继续第一关 Phase B 灰盒。首次玩家评审待收集；真机只是延后，不是通过。

## 3. 单局竖切

Phase B 灰盒已接入浏览器运行时：发条步兵与第三波起出现的疾行机按配置生成，机枪塔按“最接近出口、生成顺序”稳定索敌，冷凝塔提供不叠乘的持续减速；击杀与清场回款进入共享经济账本，漏怪由战斗状态机统一扣核心。弹道、命中、死亡、奖励和核心受损由独立表现层消费只读事件。造路门禁、暂停/恢复、胜负结算与重新部署均已回归通过；布局、战场 Renderer、HUD 和浏览器 QA 适配已从场景 Bootstrap 中拆分。8 波配置、清场奖励、8 秒波间倒计时和提前开波已接入；1×/2× 速度由统一模拟时钟以固定 60 Hz 步进驱动。当前 11 塔推荐构筑在右侧浏览器以 80/86 击毁、核心 4/10 完成八波；下排自选再补一座机枪的固定步进版右侧浏览器实战为 84/86、核心 8/10。此前 90 敌配置的证据仍保留为历史回归；真人平衡仍待收敛。当前证据见 `docs/poc/phase-b-first-level-pacing-regression.md` 和 `docs/poc/phase-b-fixed-step-regression.md`。

## 5. Phase A 当前结论

- 已验证：三种网格短折线均增加 4 格，长蛇形均增加至少 80%；14 条规则测试与 100 次动态改路回放通过。
- 已验证：Cocos Web Mobile 发布构建、右侧浏览器点击/拖拽/非法拦截/撤销/运行中改路；控制台 0 error / 0 warning。
- 未验证：首次玩家理解，首屏/整包网络压缩体积；真机触控与帧时间改为发布前补测。
- 修复项：按钮可读性与发布构建统计遮挡均已复验关闭。
- 阻断项：Phase A 工程阻断已清零；可进入第一关灰盒，不得跳过后续首次玩家决策与发布验收。

## 6. Phase B 当前结论

- 已验证：当前第一波 6 敌人生成、路径运动、稳定索敌、伤害、击杀奖励、暂停冻结、恢复和胜利结算；四塔教学开局为 6 杀 0 漏、核心剩余 10。旧版 8 敌人、6 杀 2 漏为历史回归。
- 已验证：8 波配置连续性、单波完成交接、8 秒波间倒计时和提前开波；当前浏览器实测第一、二波清场后均保持核心 10，波间可继续下一波且累计统计连续。
- 已验证：1×/2× 模拟速度循环、长帧上限、速度/塔/提前开波触控区域互不重叠；右侧浏览器 2× 下 0.5 秒真实时间推进约 1.03 秒游戏时间。
- 已验证：空场开战被“两座塔”门禁拒绝；短折线 fixture 满足 4 塔、路径 +4 后允许开战。
- 已验证：弹道、命中环、死亡消散、奖励金币和核心受损反馈可见，表现生命周期不修改战斗模拟。
- 已验证：20/30/60 FPS 三档规则模拟结果一致；28 条规则测试和 Cocos Web Mobile 调试构建通过；速度与提前开波控件已在右侧内嵌浏览器回归。
- 已验证：胜利与失败使用同一结算视图模型；结算层独占输入，重新部署恢复开战前 4 塔、金币 0、路径 16 的检查点，不带回本轮 24 金币收益。
- 已验证：发布构建中的 `Set` 快照显式使用 `Array.from`，规避 Cocos loose Babel 对 iterable spread 的不兼容。
- 已验证：机枪塔与冷凝塔异价部署、出售和检查点恢复；减速状态刷新但不叠乘，混合起手跨帧率保持当前第一波 6 杀 0 漏。
- 已验证：清场奖励连续且幂等；当前推荐构筑规则回放和右侧浏览器均为 86 生成、80 杀、6 漏、核心 4/10；下排自选多补一座机枪的规则回放为 84 杀、2 漏、核心 8/10。旧版 90 敌证据见第 12 节，仅作历史对照。
- 未验证：玩家首次理解、真人首局胜率与最终数值平衡、敌人变体的真人辨识度、正式动作素材与发布性能。首关音效链路的验证范围见第 9 节。
