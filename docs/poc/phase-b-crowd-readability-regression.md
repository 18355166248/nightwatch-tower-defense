# Phase B 密集敌群可读性回归（2026-09-27）

## 现场问题

右侧浏览器的 `?qa=1` 混合塔样例在第四波入口拐角出现 4 只活动敌人，但 78 设计像素的切图与多条血条叠成近似一只。HUD 虽有“场上人数”，却不能说明拥挤发生在战场哪里。另一个细节是选中冷凝塔后显示旧文案“减速 45%”，与当前 Lv1 配置的速度倍率 0.25（减速 75%）矛盾。

## 处理边界

- 以敌人真实 `fromCell/toCell/progress` 映射到最近格，把同格 2 只及以上的活动敌人标记为局部 `×N`；单只不显示。人数徽标位于切图上方的独立表现层，并限制在棋盘范围内。
- 该分组只读，不合并单位、不偏移逻辑坐标，不改变血量、索敌、奖励、路线或战斗节奏；数值回放应保持原结果。
- 选塔文案从塔配置生成，与已建塔属性 HUD 使用同一配置源，避免以后调减速值又留下旧说明。

## 验证

执行 `npm run verify`：65 项规则测试通过；Web Mobile 发布构建通过。规则测试覆盖两只近邻得到 `×2`、单只无徽标、异常进度兜底和冷凝文案的真实 75%/1.2 秒。原有推荐构筑八波规则回放仍为 213/213 零漏、核心 10；这不是浏览器完整首局证据。

右侧浏览器独立 QA 页 `?qa=1&build=visual-review` 已在 9×13 样例中用 `J` 布混合四塔、`Space` 开波、`X` 切 2×。第一波 4 只活动敌人重叠时截图可见局部 `×3` 徽标，第五波 6 只活动重装敌人时可见 `×5`；仍显示独立敌人切图和减速环。暂停后的只读诊断显示选中冷凝塔文案“范围减速75% · 1.2秒”。浏览器控制台未见 error/warning。四塔 QA 样例在第五波已漏 1 只，不代表默认 140 金教学路线或真实玩家识别率。正式入口已更新到 `?build=phase-b-crowd-0905` 并确认开场正常。

## 仍待验证

- 更密集的第 6–8 波、混合敌种和多组相邻徽标是否形成新的视觉噪声；需要实际画面与玩家观察。
- 浏览器默认教学构筑完整八波仍未复核；玩家是否会把 `×N` 理解为人数也未测试。
