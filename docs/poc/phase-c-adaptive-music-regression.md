# 首关夜城双层 BGM 候选（2026-09-28）

## 对应目标

总方案 `docs/NIGHTWATCH_TOWER_DEFENSE_PLAN.md` 第 9 节明确要求一条循环夜城防守 BGM 与后半关强度层。此前只有短音色，不能以音效链路通过代替完整声音体验。本轮补此缺口，不增加玩法、不迁移引擎。

使用 `audio-design` 的总线/垂直分层/音频时钟原则；实现仍为 Cocos Creator 3.8.8 的现有 Web Audio 适配，不照搬其他引擎示例。

## 声音方向与资产契约

- 原创 96 BPM、16 小节、40 秒循环，D 小调和声。基础层为低音、柔和金属铃音与稀疏和声；强度层为机械短脉冲与额外低音，不换主旋律。
- 无第三方采样、现有游戏录音或外部曲谱；源码乐谱和合成器是源文件。商业权利/原创性与最终审美仍需人工复核，不以“程序生成”自动认定正式审批通过。
- 运行时首次用户手势后分批生成两个 22050 Hz 单声道 Float32 缓冲；两层常驻合计 7,056,000 B（约 6.73 MiB），生成时另有同量级临时数组。无新增音频网络资源，WAV 仅供 review，不进入构建。
- `night-city-music-review-v1.wav`：50 秒、22.05 kHz/16-bit/单声道、2,205,044 B。前 20 秒基础层，20 秒起渐入强度层，40 秒跨循环接缝，继续 10 秒。按运行时最高档增益渲染，参考峰值 -35.020 dBFS，不归一化；此峰值不代表音乐与炮声共同播放时的实际输出响度。
- 当前是试听候选；耳机/扬声器的舒适度、金属音是否刺耳、长循环疲劳与警报辨识尚未审批。

## 分层与生命周期

- `FirstLevelMusicScore`：只保存谱面与纯样本生成，跨循环尾音回卷；同一谱面生成运行时缓冲和离线试听。
- `FirstLevelMusicPolicy`：只读已有阶段。首页/结算不播；布防、前四波和教学待命用基础层；第五波起用强度层；真实暂停冻结音乐。
- `BrowserLayeredMusic`：两个源共用启动时间/offset，Music 总线接入 Master；换强度时等下一个小节，平滑改变第二层增益，循环点不重建音源。音乐时钟不读模拟 delta 或速度。
- 警报/开波/胜败等被短音预算接受后，Music 总线下降 10 dB，尾后缓慢回升；无逐枪声抽吸。两条循环不占 12 个短音预留声部。
- 暂停/静音停止两个旧源并保留音乐 offset，继续时整组重建；重开、空场重置、首页、胜败清 offset。异步生成完成不能自行播放，必须等待当前阶段和输出授权允许。
- 生成/输出失败静默退回原有音效和完整无声玩法；设置仍复用原 Master 四档与总开关，不新增存档 schema。HUD、设置页、状态文案与读屏文案统一称“声音”，避免把音乐开关误写成仅音效。

Web Audio API 语义参考 [start 的调度时间与 offset](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/start) 与 [setTargetAtTime 渐变](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime)。
