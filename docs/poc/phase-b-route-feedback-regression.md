# 第一关布塔改路反馈回归（2026-09-26）

## 目标与边界

让第一关最核心的“布塔改变敌人路线”可被直接感知。预览阶段显示相对当前真实路线的增减格数；提交或准备态撤塔后，真实新路线短暂描边。反馈是独立展示状态，只读 `PlacementModel` 已算出的流场与路径，不调整寻路、扣费、战斗或波次规则。

## 实现边界

- `RouteChangeFeedback` 负责路径差值、文案和 0.9 秒的展示生命周期，使用真实时间而非 1×/2× 战斗时间。
- `NightwatchPocBootstrap` 只在合法预览、提交成功和撤塔成功时提供当前/新流场长度；非法预览、陈旧提交不创建成功反馈。网格重置、重新部署会清空旧效果。
- `PhaseBCanvasRenderer` 消费只读快照，延长路线用绿色、缩短路线用暖色描绘当前路径格边框；新预览出现时不描旧路径，避免误导。

## 验证

| 场景 | 证据 |
|---|---|
| 规则层 | `npm run verify` 38/38；预览路径长度与提交后的流场差值相等，撤塔得到反向差值，效果按真实时间消失 |
| 发布构建 | `npm run build:web`，Cocos Creator 3.8.8 Web Mobile 构建通过 |
| 右侧浏览器合法预览 | 推荐开局第三塔预览时 HUD 显示“可建造 · 路线 +2 格 · 再点确认”，绿色候选路线与 14 格路径一致 |
| 右侧浏览器提交与撤塔 | 确认后 12→14 格、顶部显示“路线 +2 格”，新路径绿色描边约 0.9 秒后恢复；二次点击已建塔撤销后 14→12 格、顶部显示“路线缩短 2 格”，暖色描边出现 |
| 错误 | 浏览器控制台 0 error / 0 warning；`git diff --check` 无空白错误 |

## 未验证

首次玩家能否无需引导理解“延长路线换取输出时间”、不同布局下是否愿意主动改路，以及真机上的动效可读性；这些不能由单次浏览器回归替代。按当前用户要求，此轮不做 Android 真机测试。
