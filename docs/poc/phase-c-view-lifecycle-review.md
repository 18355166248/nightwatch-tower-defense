# 首关首页与暂停文字的可见生命周期

2026-09-28；固定 Cocos Creator 3.8.8、右侧浏览器发布构建。只减少隐藏界面的纹理持有，不缩画质、不迁移、不扩玩法。

## 实际原因与测量边界

上轮发现GFX计数超预算，本轮追踪文字所有者而非继续猜差值。固定引擎 `Label.onDestroy` 会销毁TTF SpriteFrame/纹理；仅隐藏Node仍持有纹理。新诊断读取固定版本的deprecated `Label.spriteFrame` getter，并隔离在 `CocosRenderBudgetProbe`；玩法/视图生命周期不依赖这个内部接口，不调用内部纹理销毁方法。

纯 `LabelTextureBudget` 按实际GFX所有者去重，合并可见持有者；资源缓存共享分配单列，不假装销毁文字即可释放。版本缺测/非法字节返回null，不以0放行。当前Labels使用现有默认NONE缓存，未更换字体或改成字符图集。分类只覆盖当前场景Label引用，不证明所有引擎字体/全局缓存所有权；隐藏量是追踪线索，释放结果以实际GFX差值再验证。

新增计数最初在发布版暴露了Creator loose展开兼容问题：`[...Map.values()]` 被转为 `[].concat(iterator)`，出现NaN/null与空对象。已改显式 `Array.from`、重建并在浏览器核对真实分配；初次失败快照标为拒收，**不用于优化前基线**。151项测试后的12:34:18诊断构建提供有效基线，不把Node单测通过当发布计数正确。

## 实现与复用

- `VisibleViewResource<T>`只处理“可见创建/复用→隐藏释放→再次可见重建”；重复快照不重复创建/释放，释放前断开所有权。无引擎、经济或输入依赖。
- 首页六项文字独立 `HomeLabels` 子树；离开首页仅销毁自己的子树，通过Cocos正常Node销毁释放文字。返回首页重新按原字号、位置、颜色、文本和记录快照创建。教学跳过、Graphics、首页图片和玩家记录不被销毁。
- 实测又定位到已关闭暂停菜单的约300KB级文字，复用相同模块管理 `PauseLabels` 子树。菜单/设置/确认/横屏提示依然消费原状态与几何；只有整个覆盖层不可见时释放，不在各子页切换中重写规则或设置。
- 仅作用于这两种视图自己的Node；不手工释放SpriteFrame素材、共享字体、动态合图或图片缓存。装配/战斗规则与结算HUD均未改。
