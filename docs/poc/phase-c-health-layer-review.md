# 地面遮挡与密集血条 review（2026-09-28）

## 本轮变化

上一轮普通1×整局截图暴露重甲叠群。本轮用 game-ui-ux 的信息层级原则做一项具体改善，保持 Cocos 3.8.8，不改寻路、伤害、碰撞、生成速度、经济、角色尺寸或关卡。

- 身体不再按出生顺序遮挡：脚下地面Y从后到前排序，同地面位置以出生序稳定打破并列；只在兄弟序确实变化时重排节点。
- 血条从身体子节点分离，所有角色和短尸影绘制后再画，避免后出生单位盖住前方血条。满血/死亡仍不画，受伤比例仍逐只读取真实生命。
- `EnemyHealthBarLayout` 只接收候选几何和棋盘边界，不依赖Cocos或模拟对象；出生序确定局部15个槽位，优先减少冲突，再选最小位移。竖直最多44设计像素，横向最多一条血条宽加8；显示条与引线锚点均夹在棋盘内。
- `EnemyHealthBarView` 是共享画法，Sprite与缺图灰盒都消费同一布局；位移超过12设计像素才画低对比引线。极端拥挤不隐藏受伤敌人的生命条，有限槽位挤满仍可能重叠，诊断显式报告冲突。

新增诊断 `renderedEnemyHealthBarCount`、`displacedEnemyHealthBarCount`、`overlappingEnemyHealthBarPairs` 为切图层实际输出计数；缺图灰盒不由这三个切图计数证明。原 `visibleEnemyHealthBarCount` 仍是受伤候选数，不能仅用它断言已经绘制。
