# 首关 Cocos 纹理分配与小图集候选

2026-09-28；固定 Cocos Creator 3.8.8 Web Mobile 发布构建。仅浏览器候选，不迁移引擎、不做 Android 真机。

## 为什么继续测

上一轮的7.14 MiB只包括运行图片，不含文字、内置纹理、动态图集与渲染目标。本次先加只读计数，再定位和减少实际发生的大额动态合图分配，遵循 performance-optimization 的先测后改流程；不把降低内存称作帧率提升。

## 解耦与证据口径

- `RenderBudgetSummary`：纯数值边界、公开TextureView所有者追踪与去重前提。缺测/非法值返回null，差值矛盾不制造负数，页面内采样峰值单调。
- `CocosRenderBudgetProbe`：仅使用公开的 `director.root.device.memoryStatus`、`numDrawCalls`、`Texture2D.getGFXTexture()`、`Texture.viewInfo` 和 `assetManager.assets`，每500ms遍历一次；装配层只合并诊断快照。不修改玩法、渲染帧或缓存。
- Cocos的 `getGFXTexture()` 返回视图，不是分配本体；沿公开 `viewInfo.texture` 找所有者，再按本体去重。不能跳过所有view后误报0，也不能为多个view重复计费。
- `RenderAtlasPolicy`：纯初始化边界。仅 `renderBudget=small-atlas` 启用；在创建首关视图前设置512方、最多2张、最大帧128。不改变原本关闭的图集，已有打包纹理时保守拒绝，不reset、不释放既有帧、不修改图片缓存清理宏。放不进图集的碎图继续使用原纹理，不丢图。
- 可移除候选参数退回默认2048图集；`artBudget=compact`只选素材尺寸，两者互不隐式启用。未知参数也保留默认。

数字是引擎GFX账面分配，**不是硬件物理显存或进程总内存**；固定引擎实现不计swapchain。缓存分类只覆盖资源缓存的Texture2D，未分类差值不能直接归因字体、泄漏或某个渲染目标。500ms采样峰值不是捕获所有瞬时分配的真实最高值；绘制批次是对应单帧读数，不是均值、GPU时间或帧率证明。
