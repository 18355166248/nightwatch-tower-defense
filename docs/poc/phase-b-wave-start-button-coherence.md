# Phase B 首波与波间开波按钮一致性（2026-09-27）

## 现象与边界

上一构建 `phase-b-opening-review-1235` 在两座机枪 `(4,2)`、`(5,2)`、80 金、路线 14 格时已满足真实首波门槛。中央 ▶ 高亮、引导提示“可提前开波”，但右下角仍是灰色“提前开波 / 等待中”。点击右下角实际得到“只能在波间倒计时提前开波”的拒绝反馈。这是同一画面中操作状态相互矛盾，不是数值门槛问题。

现在右下角按钮按阶段展示：

| 阶段 | 按钮 | 点击路径 |
| --- | --- | --- |
| 尚未满足首波门槛 | 灰色“第一波 / 先布防” | 仍由首波状态机解释缺少炮塔或路线，不会开波 |
| 已满足首波门槛 | 绿色“开始 / 第一波” | 与中央 ▶ 共用 `toggleBattle()`，生成同一开战检查点 |
| 自然波间倒计时 | 绿色“提前开波 / N 秒” | 使用原有波间提前开波状态转换 |
| 教学清场后待命 | 绿色“开始 / 下一波” | 与中央 ▶ 共用教学续波入口 |
| 其他战斗阶段 | 灰色“提前开波 / 等待中” | 不改变战斗阶段 |

按钮文案与着色由同一纯展示函数生成，渲染层仅消费只读快照；输入层仍只负责把点击送往已有开波流程。画布读屏在教学待命时同步报告“下一波可开”，不再误报未激活。没有更改经济、波次、敌人或路径规则。
