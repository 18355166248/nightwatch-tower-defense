# 第一关出口核心持续反馈回归（2026-09-26）

## 起因

此前核心剩余生命只混在顶部细小状态文字中，出口格只是红色方块；玩家在密集战斗中很难一眼判断“守的是什么、还可漏几只”。本轮只增强该决策信息，不调整索敌、伤害、漏怪或波次。

## 实现边界

- `CoreObjectiveState` 根据真实 `coreHealth/maxCoreHealth` 生成剩余比例和健康/受损/危急状态；纯函数不写入战斗状态。
- `CoreObjectiveView` 只消费场景只读快照与网格布局：出口上显示生命弧线，战场左侧留白显示数字和最多 10 段血量。数字与血条放在格外，避免阻挡点击和布塔；原核心受击短暂红圈仍由战斗反馈层负责。
- `PhaseBCanvasRenderer` 只负责调用该独立视图；`NightwatchPocBootstrap` 增加核心生命到绘制快照。未新增图片资源，正式 HUD 和出口资产仍在 `docs/first-level-art.md` 清单中。

## 验证

- `npm run verify`：40 项规则测试通过，覆盖满血、9/10、4/10、2/10、0/10、QA 低核心上限与非法上限输入。
- `npm run build:web`：Cocos Creator 3.8.8 Web Mobile 发布构建通过。
- 右侧浏览器 `http://127.0.0.1:4176/?build=core-objective-final-0356`：开局侧边徽章显示 10 和十段亮条，出口有完整圆环；按四塔教学走到第三波后，顶部核心 9 与侧边数字 9、九段亮条及缩短的出口圆环一致。四塔布防、两次补塔和波次继续正常，浏览器 error/warn 日志为空。首版把数字塞在出口单格里过小，最终改为侧边徽章并放大数字。

## 尚未验证

这里只证明功能读数与浏览器画面一致，未做无提示玩家理解度测试、真机安全区/不同屏宽验证，也未完成正式核心图标和出口切图。按当前用户要求不做 Android 真机测试。
