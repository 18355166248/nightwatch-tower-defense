# Phase B 首关开波门槛与推荐布防区分（2026-09-27）

## 问题与改动

旧版战斗规则允许至少 2 塔且路线增加至少 2 格时开第一波，但教学主要要求完成推荐 4 塔、+4 格横墙。右侧浏览器实测两座机枪 `(4,2)`、`(5,2)` 后已达到真实门槛（80 金、14 格路线），底栏仍只显示“推荐布防 3/4·继续横向补齐墙”，没有说明此时可以挑战。

现在战斗状态机导出并使用同一组硬门槛常量，教学区分“可提前开波”和“推荐四塔”。未达到推荐构筑时保留可选建塔引导，同时提示火力/路线风险、描出 ▶ 入口；达到四塔 +4 格时仍按原推荐流程提示。画布读屏状态在开局报告“第一波可开”或“第一波待布防”，不再误报“提前开波未激活”。没有提高硬门槛，也没有自动补塔或改战斗数值。

## 开波时取消未提交预览

在两座机枪 `(4,2)`、`(5,2)` 已提交且满足开波门槛后，先单击 `(3,2)` 预览第三座机枪，**不再点击确认**，然后点 ▶。旧构建 `phase-b-preview-start-baseline-1207` 进入 `spawning` 后仍显示第三塔虚影和候选 16 格路线，诊断状态为 `inputMode=click-preview`、`previewAccepted=true`，但实际只提交了 2 塔、金币仍为 80、地图版本仍为 2。画面候选路线与敌人的真实流场不一致。

现在所有开波入口共用的 `startCurrentWave()` 会清除未提交输入。相同步骤在 Web Mobile 新构建 `phase-b-preview-start-fixed-1206` 中进入 `spawning` 后显示已提交的 14 格路线，`towerCount=2`、`gold=80`、`mapVersion=2`、`inputMode=idle`、`previewAccepted=null`；第三塔虚影消失。右侧浏览器 `error`/`warn` 日志为空。该改动只收尾输入状态，不改变建塔事务或敌人寻路；尚未覆盖其他设备的触摸中断路径。

## 尚未验证

- 风险文案是否真的让首次玩家理解“可挑战，但推荐先补塔”，需要至少 5 名新的无口头指导玩家观察；作者操作不能代替理解率。
- 新版风险提示标签没有重跑八波；推荐四塔完整八波的历史工程回归见 `phase-b-default-manual-eight-wave-regression.md`，本轮只复核首波。
- 按当前要求仅测右侧浏览器，不做 Android 真机。Phase B 仍未通过。
