# 第一关 HUD 饰面试点：右侧浏览器检查

日期：2026-09-27。设计目标与候选切图见 `phase-c-hud-direction-v1.md`。本次只把合成稿里的“上方四资源槽、下方深色托盘、铜色细边”的视觉原则落入现有 Cocos 绘制层；合成稿及金币图标尚未接入运行时。

- 实现：`FirstLevelHudChromeView` 单独负责无交互底框和四资源卡饰面。`PhaseBCanvasRenderer` 保留战场/控件绘制，控件增加选中/可买/禁用边框。`PhaseBLayout` 仍是卡片和按钮几何的唯一来源，`PhaseBHudView` 仍负责动态数字与文案；战斗、经济、输入和 Sprite 加载逻辑没有改。
- 验证：`npm run verify` 通过 87 项规则测试；Cocos Creator 3.8.8 Web Mobile 调试构建与发布构建完成。右侧浏览器曾在约 390×600 窗口查看入场页、初始 HUD、选中机枪塔、同格两次确认落塔。画布读屏从 140 金/0 塔变化为 110 金/1 塔，边框与数值仍同位，浏览器 error/warn 均为空。
- 最终构建：健康核心色条保持青绿、核心 ≤3 才转暖红。重建发布包后又在右侧浏览器 `http://127.0.0.1:4176/?build=phase-c-hud-chrome-final-1237` 查看入场及初始 HUD；核心 10/10 的数值与青绿色条正确，浏览器 error/warn 为空。此最终构建未重复落塔，落塔检查来自前一构建；最终修正仅涉及饰面颜色。
- 待评审：程序饰面离合成目标还有距离，尤其标题/事件行仍较密、底栏主按钮视觉占比不足。图标系列、底框正式透明切图、选中/按下动效、真人小屏可读性和商业资产审查均未完成。现有浏览器操作只证明本次饰面没挡住首个落塔，不证明完整八波或首次玩家体验达标。
- 按用户当前要求，仅用右侧浏览器验证，不进行 Android 真机测试；Phase B 的新玩家验收门槛仍未通过。暂不迁移引擎。
