# 窄屏首页、HUD与完整棋盘

2026-09-28；沿用 Cocos Creator 3.8.8，仅右侧浏览器。最终发布构建13:03:35 / `phase-c-responsive-entry-1303`，不做迁移或Android真机。

## 实际问题与共享布局

上一轮320×900暴露：右侧声音按钮经 `safeRect` 直接裁窄，只剩约7个设计像素；首页设置文字仍固定在原位置；引导换行超出100高文本槽；棋盘765宽大于窄屏可见宽683，外列触控贴边。

game-ui-ux技能影响实现方式：不是只改文字位置，而是让按钮底板、Label和输入共用同一套几何；保持字号，不通过整体缩小HUD掩盖裁切。

- `PhaseBLayout.fitRect`供独立边缘按钮整体内移，保留原宽度；常规屏无越界时保持原矩形。与用于已有分区裁边的 `safeRect` 分开，不把所有控件一刀切平移。
- 新无引擎 `FirstLevelEntryLayout`返回首页卡、开始/设置、标题与正文宽度。窄屏标题和设置并排，按钮和文字卡内对齐；介绍卡只收敛列间距，不缩小图片/说明文字或重新加载图片。输入直接读取相同按钮矩形。
- 首版实测发现内移后的“跳过”会挤到波次标题；最终在极窄屏放到顶部标题与声音间空位，常规屏仍用原行。绘制/文字/命中共用 `firstLevelCoachSkipRect`，并限制单行事件不延伸到声音按钮下。
- 小于550宽的引导槽使用下方空闲区，允许最多四行50行高，底部仍在商店上方；点塔时由升级/出售接管，原显示条件不变。首条冗余“占住上路”改为明确“点上路”，消除实际截图中的单字孤行，不省略改路指令。
- 棋盘显示格宽受同一安全边界约束，320×900默认9×13由85显示格宽变70，完整630宽留在安全区内。模型仍按格坐标运算；指针、预览、路线、角色和核心共用原 `boardMetrics/gridPointCenter`，不改变格子数、经济、射程或步进时钟。普通390×844、430×932仍是85格宽。
- 重装的极窄屏显示策略显式传给 `enemyDisplaySize`；行走/死亡共同遵循格宽，常规屏及旧QA网格保留原策略。首次改成所有小格都收敛时，既有默认QA网格尺寸测试失败，已隔离为显式窄屏策略，未删除旧断言；最终158项全部通过。
