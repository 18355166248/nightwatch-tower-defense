# 动态道路实体路面候选与浏览器回归（2026-09-27）

## 目标与实现边界

- 把原先覆盖在石板底图上的半透明路线描边，调整为与当前寻路结果同步的实体道路：外阴影、铜色边缘、暗槽、石板面、转角圆弧和稀疏板缝。保留原有方向箭头、改路预览的绿色新路/划线旧路反馈。
- `RoadSurfaceGeometry` 只从正交路径提取转角和直路板缝；`DynamicRoadView` 只负责 Cocos Graphics 绘制；`BattlefieldSurfaceView` 负责组合。道路不烘焙到底图，不另存一份寻路状态；放塔导致改道时，路面与玩法路径共用输入。
- 本次没有改敌人寻路、塔伤害、波次或经济，也没有新增正式道路贴图。该视觉候选用来验证材质层级和手机宽度可读性，不作为最终美术验收。

## 验证

- `npm run verify`：97/97，通过；覆盖正交转角、隔格接缝以及非相邻点不伪造道路特征。Cocos Creator 3.8.8 Web Mobile 发布构建通过。
- 右侧浏览器 `http://127.0.0.1:4176/?build=phase-c-dynamic-road-final-1901`，普通玩家入口、350×600 视口：开局 12 格直路；按推荐依次放 `(4,3)` 机枪、`(5,3)` 机枪、`(4,7)` 冷凝、`(3,7)` 机枪后为 16 格折线路，金币 `140→10`。第一座塔预览为绿色新路 + 划线旧路，确认后回到中性色道路。
- 1× 首波实战：9/9 击毁、0 漏、核心 10/10、金币 54；敌人在两处转弯及右侧长直路上仍可辨，板缝没有盖过单位、箭头或冷凝反馈；浏览器控制台 0 error/warn。

## 观察与后续

- 在 350 像素宽下，道路实体感优于旧半透明描边，但直路板缝仍刻意保持低对比；不能把这一轮静帧观察当作 5 名新玩家的路线识别率。铜边/石板色与后续正式切图需统一验色，尤其要检查高密度第 6–8 波的敌群遮挡。
- 本构建只完整实测第 1 波；上一构建的 1× 八波胜利记录不能直接视为这个新构建的八波实测。正式美术、音效、动态录屏评审和无指导玩家测试仍未完成；按用户要求不做 Android 真机测试，也不据此决定迁移引擎。

后续同构建已由作者在普通入口 350×600、2× 手动跑完八波，结果为 212/213、漏 1、核心 9/10、控制台 0 error/warn；见 `phase-c-dense-wave-briefing-regression.md`。这补齐了本构建的高密度道路回归，但不把 2× 结果当作真人 1× 局长。
