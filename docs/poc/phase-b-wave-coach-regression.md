# 首关逐波布防与 HUD 单行回归 · 2026-09-26

## 原因与改动

前一版推荐构筑有三座塔整局零开火。逐塔开火与移除单塔后的流场对照表明：左侧 `(1,2)` 虽不开火，却能改变最终路线；`(0,2)` 和下排 `(5,8)` 在该构筑中既不开火，也没有单塔可观测的路线作用。若直接删去两座左侧塔，敌人会走另一侧，使下排火力区失效，规则回放第七波核心归零。因此没有把“零开火”直接当作无效塔。

现行推荐保留 `(1,2)` 封路，去掉 `(0,2)`，把下排机枪放到能接敌的 `(6,8)` 与 `(7,10)`。`FIRST_LEVEL_REINFORCEMENTS` 每项带 `afterWave` 与简短目的：第一波后延长路线、第二波后预封左路、第三波后导向右侧、第四波后在重甲登场前补冷凝、第五与第六波后补下排火力。玩家仍可自由布塔；逐波限制只约束教学提示和推荐回放。首波机枪升级仍是建议，不替玩家自动操作。

点选塔时，顶部只显示等级、射程与伤害/减速的单行摘要；撤销限制留在底部帮助行，升级价格仍由独立按钮显示。事件行关闭自动换行并限制自身高度，避免长文案压到金币、路径、波次和核心。第二、三波在新增前排火力后略收紧生成间隔，保持多敌同屏且不靠空场等待拉时长。

## 当前推荐回放

口径：固定 60 Hz、第一波后升级初始机枪、每波清场后只按当前 `afterWave` 项补一座塔；秒数是纯模拟战斗，不含玩家思考或教学停留。复现：`npm run verify`、`node scripts/compare-first-level-strategies.cjs`。

## 浏览器复核与边界

58 条规则测试、Cocos Web Mobile 发布构建通过。右侧浏览器约 377×602 视窗按真实触控流程完成四塔开局、首波升级、每波一次推荐补塔和八波结算；第一波 `(6,2)` 预览路线 +2，第二波 `(1,2)` 预览路线不变但为后续改道封左支路，第三波 `(7,2)` 预览再 +2 并把路线推到右侧。机枪/冷凝点选后顶部单行摘要不再覆盖资源栏。浏览器以 2× 推进战斗，最终同样 123/123、0 漏、核心 10/10、金币 592，控制台无 error/warning；这不是真人首局耗时证据。

混合构筑投入 344 金、同格纯机枪投入 324 金，两者规则回放均零漏；因此**冷凝的等预算价值仍未通过**。初步参数搜索发现单纯提高减速不够，而把纯机枪放在冷凝格位可能恰好超出射程，制造虚假的混合优势；后续对照必须同时核查预算、逐塔开火、改路作用，并允许纯机枪采用自身有效塔位。未升级推荐构筑只在末波漏 1 只，升级决策收益还偏弱。金币结余大、1× 时长短、真人理解率与首局胜率均待继续调校；按用户要求此阶段不做 Android 真机测试。
