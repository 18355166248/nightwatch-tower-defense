# Phase B 首关首次玩家灰盒试玩（待执行）

本轮目标是验证“无需作者讲解即可理解、愿意玩完一关”的真实体验，不把作者操作、QA 自动购买或规则回放计入样本。原始门槛见总计划 §12.4；此文档只把执行和记录步骤固定下来，不预填结果。

## 招募与环境

- 邀请至少 5 名没有接触过本游戏的新玩家；一人只计第一次完整尝试。记录匿名 ID（例如 `P01`），不要填姓名或个人联系方式。
- 使用同一个已构建的 Web Mobile 版本和默认玩家链接；URL 不带 `qa=1`，游戏全程保持 `1×`。测试前记录构建标识、浏览器、设备视口，并清理本机最快纪录对测试者的潜在暗示。不要用作者的旧存档或续局。
- 作者只读出统一开场语：“请像第一次接触的玩家一样玩这一关；我不会解释玩法。想停可以随时停。”开始后不口头指导、不指格子、不替玩家点击。技术故障可以终止并记录，不能改成成功样本。
- 用户当前要求以右侧浏览器测试，不做 Android 真机；浏览器样本不能替代将来的真机门禁。

## 一人一局的观察顺序

1. 从玩家看到战场开始计教学真实时间，记录首次真正开波的秒数；没开波就留空。记录首次造出让路线变长的布局之前是否主动退出。
2. 只观察并记录：错误放置及自恢复、重复扣费、输入锁死、是否使用 2×/QA、结算胜败和退出位置。不能在中途给出建议。
3. 胜利时抄结算卡“局内用时”，换算为秒填写 `victory_elapsed_seconds`；它排除教学停留、人工暂停，计入正常倒计时。失败局不填胜利局长，另在观察笔记记录波次与失败原因。
4. 结束后先问两个开放问题并保留原话：“摆塔后敌人路线会怎样变化？”“机枪塔和冷凝塔分别有什么作用？”观察者依据是否说出“造路/改路”和“输出/减速”分别给 1 或 0；不要先念标准答案。
5. 保存该局录屏、截图或带时间戳观察笔记，在 CSV 的 `evidence_ref` 填相对路径或可定位的文件名。单独记录玩家停顿、误解和原话；CSV 只放判定所需的匿名结构化字段。

## 录入与判定

把每名玩家一行追加到 `docs/poc/phase-b-first-player-sessions.csv`，填写同一 `build_id` 和各自的 `browser_viewport`（如 `IAB 360x780`）。布尔项填 `1/0`；`result` 只能是 `victory`、`defeat`、`quit`。`tutorial_completed=1` 指实际成功开启第一波，不是点过提示；`speed_1x=1` 指全程没有切 2×。无胜利局长或未开波的教学耗时留空，不填 0。

运行：

```bash
node scripts/phase-b-playtest-evaluator.cjs docs/poc/phase-b-first-player-sessions.csv
```

输出 `invalid` 是样本缺失或口径不符，不能拿来算通过；`fail` 会逐项显示未过门槛；只有 `pass` 且原始证据复核无误，才可申请 Phase B 真人门禁通过。脚本用全部玩家计算教学耗时中位数：没开第一波视为未完成，不会被悄悄从中位数剔除。首局胜率必须为 60%–85%，胜利局长中位数为 360–480 秒，教学完成率/两项理解率各 ≥80%，重复扣费与输入锁死均为 0，首次造路前退出少于 2 人。5 人仅作形成性判断，不声称统计显著；失败后按录像定位教学、地图空间、数值或反馈问题，再招新的首次玩家复测。
