# 首关战场亮度与单位可读性复核（2026-09-27）

## 目的与改动

参考用户提供的《Fieldrunners 2》截图检查当前首关，不复制其素材。原战场的全屏夜色与棋盘罩色叠加，地面纹理和路线均偏暗；塔与小怪在约 400 像素宽的浏览器游戏画面中也偏小。

- `PhaseBCanvasRenderer` 全屏夜色 alpha `65→48`，`BattlefieldSurfaceView` 棋盘局部罩色 `64→18`，道路改为更清楚的暖铜边、灰石中心。道路依旧按当前流场路径实时描绘，建塔后立即更新，不用固定底图烘焙道路。
- `UnitDisplaySize` 统一炮塔和敌人的显示尺寸；普通小怪按格宽轻微放大，重装上限为 98 设计像素。`PhaseBUnitSpriteView` 的存活与死亡节点复用同一尺寸规则，现存敌人节点在 QA 网格切换时也更新画布。炮塔画布不超过单格；逻辑格、火力和输入热区均不改变。
- 这些只是分层、比例和对比度微调，不引入新玩法、不修改数值，也不把候选单位切图误标为正式资产。

## 自动与浏览器验证

- `npm run verify`：93/93 通过，包含三种网格的显示画布约束；TypeScript 检查通过。`npm run build:web` 完成 Web Mobile 发布构建。
- 右侧浏览器 `http://127.0.0.1:4176/?build=phase-c-unit-readability-1610`，无 QA 参数，从普通玩家入场卡开始。手动依次放 `(4,3)` 机枪、`(5,3)` 机枪、`(4,7)` 冷凝、`(3,7)` 机枪：金币 `140→10`，路径 `12→14→14→14→16`；相邻上路双塔未相互遮挡。
- 1× 启动第 1 波，在中段观察 9 只步兵、冷凝圈、血条、射线与敌群人数徽标。末尾 9/9 击毁、0 漏、核心 `10/10`、54 金；波间中段机枪升级目标高亮可见。控制台 `error/warn` 均为空。

## 当前视觉判断与后续门槛

地面石板比旧构建易见，路径与人物层级也更清楚，但和参考截图的鲜明、紧凑、连续反馈相比，当前画面仍偏暗、空白地表占比较大；单位是两帧步态及程序化攻击/减速反馈，缺正式受击、死亡、弹道与环境动效。不能用“能通关”代替“观感达标”。

本构建只做了默认浏览器尺寸的首波回归，没有重跑八波、其他视口或至少 5 名无指导首次玩家；玩家辨识率、误触率、局长分布与正式美术评审仍待收集。按用户要求不做 Android 真机测试。迁移 Godot 的判断应留到首关同一玩法、同一素材的视觉/操作对照后，不能把美术与动效债务归咎于 Cocos。
