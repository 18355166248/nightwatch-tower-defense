## 设计决定与边界

- 中央战场尽量完整露出；常驻资源集中在上缘四格，事件只占其下一条独立窄槽。金币用暖金、路径/波次用青蓝、核心低血量才用暖红。
- 下缘只留两座塔、开波主操作、速度和暂停。两座塔实际显示仍使用现有 `rivet-gun`/`frost-coil` Sprite，不采用概念图里重新想象的塔外形。数字、中文、状态与点击区域全部由运行时代码承担，不能烘焙进位图。
- 合成稿经 `image_gen` 参考仓库现有 `backdrop.jpg` 制作，但生成过程改变了建筑细节、铺装和 HUD 占比。它不是原底图的像素级覆盖，因此**不得**直接替换 `backdrop.jpg` 或作为关卡碰撞/路径底图。
- 切图样本是对概念稿左上金币做提取编辑。第一次候选透明留白过大，缩到手机图标尺寸后主体太小；v2 放大金币主体后，32×32 可认出三枚金币。原始 v1 留档用于评审失败原因，生产候选只看 v2。
- 图标源图和归一图经 `file`/`sips` 及资产报告检查为 RGBA，alpha 最小 0、最大 255，内容边界 `(7,15)–(121,118)`；Cocos 以 `sprite-frame` 导入。右侧浏览器已在 360×780、430×932 和默认窗口检查金币图标与动态数值，浏览器日志无 error/warn。正式玩家主观认可、商业权利与持续性能仍未验收。

## 后续切图契约（样稿通过后执行）

| 元件 | 建议制作方式 | 动态内容/命中边界 |
|---|---|---|
| 四个资源位底框 | 单独透明 9-slice 或程序绘制，不切整条带数字的 UI | 每格数值独立 Label；金币、路径、波次、核心分别更新 |
| 金币/路径/波次/核心图标 | 独立透明方图，32–48 px 实际显示；先用金币 v2 试点 | 装饰图不接触控；颜色不能是唯一状态提示 |
| 事件窄槽 | 可伸缩底框，不含文字 | 长文案截断/换行规则由 HUD 视图负责 |
| 塔位底框 | 两个可复用槽位，选中/买不起/可购买三态 | 图标复用现有塔切图；热区仍来自 `PhaseBLayout` |
| 开波、速度、暂停 | 各自独立按钮面/图标，至少正常/按下/禁用或暂停态 | 视觉边界与实际热区同源；数字/中文独立 Label |

## 交叉评审点

1. 在 337×600 预览中，是否接受“上缘资源条 + 大面积空战场 + 下缘铜质操作托盘”的方向？尤其主按钮是否过大、底托是否过厚。
2. 金币 v2 的亮金是否与原有铜/青蓝塔图太跳？若跳，先校正单图再批量生成其余三个资源图标。
3. 原合成稿的建筑/地面变化**不计入**这轮美术方案；运行时继续保留现有底图。单枚金币已作引擎内种子试点，但其余图标、底框和按键仍要在方向获认可后逐个制作。
4. 继续使用现有 Cocos Creator 3.8.8 实现这一关的视觉闭环。若小屏可读性、帧率或维护成本在样稿接入后仍明显不达标，再用同一交互/视觉契约评估是否迁移 Godot；不提前双线维护。
