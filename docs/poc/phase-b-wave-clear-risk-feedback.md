# Phase B 带损清场反馈（2026-09-27）

## 问题

自由两机枪 `(4,2)`、`(5,2)` 起手在首波只击毁 2/9、漏 7、核心降至 3/10；旧事件行却仍说“第 1 波守住”，并把回款写在最显眼的位置。它在规则上是未失败，但对下一波决策来说“守住”弱化了风险。

## 实现边界

- 战斗运行时只记录**本波**漏怪数，每次进入统一开波入口清零；清场文案不使用整局累计漏怪。
- 零漏仍显示“守住”和原有清场回款明细；有漏但核心高于 3 显示“有损守住”，有漏且核心不高于 3 显示“险守”。带损事件行优先显示漏怪数和本波总回款，避免长文案在窄屏上截掉风险信息。
- 原本设想改变波次横幅颜色和文字，但浏览器发现教学清场时该横幅会被下一波敌情替代；因此最终保留实际可见的事件行反馈，未增加无效的展示分支。
- 未改怪物、塔、生命、金币事务、奖励金额、波次转换或现有核心受损视觉。

## 验证

- `npm run verify`：87/87；新增的零漏、有损、危急文案断言通过。Web Mobile 发布构建完成。
- 右侧浏览器 `phase-b-risk-clear-1220`，无 `qa=1`，作者手动摆放上述两塔，1× 点右下角开首波。清场仍为 2/9 击毁、7 漏、核心 3/10、96 金（含清场 8 金），画布辅助描述和实际事件行均为“第 1 波险守 · 漏 7 · 回款 +16”；窄屏完整可见，`error`/`warn` 为空。
- 零漏推荐构筑本轮未重新跑浏览器首波；零漏文案由规则测试覆盖，历史推荐四塔首波 9/9 工程证据见 `phase-b-opening-gate-vs-recommendation.md`。浏览器结果不等于真人对警示的理解率。
