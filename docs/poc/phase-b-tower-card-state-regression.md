# Phase B 首关塔卡“建议 / 已拿起”状态回归（2026-09-27）

## 问题与边界

默认开局内部记住机枪塔类型，但输入仍是 `idle`；此时点网格不会建塔。旧画面却按“记住的塔类型”给机枪卡画选中描边，教学又给同一张卡画外框，360×780 上像是已经拿起，首次玩家可能误判为网格点按失灵。

本轮只改展示语义，不改选塔、拖放、预览、扣费或波次规则：输入状态派生出 `activePlacementTowerId`，仅 `tower-pressed / armed / dragging / click-preview` 让塔卡出现操作描边；`idle` 即使记住上次塔类型也不显示操作描边。教学的“请点此塔”改成卡片上方指针，避免和操作描边混淆。辅助描述在空闲时说“未拿起炮塔”，活动输入时才说“已拿起机枪塔/冷凝塔”。派生逻辑独立放在 `assets/scripts/input/TowerPlacementMode.ts`，场景只把只读字段传给 HUD 和绘制层。

## 验证

- 69 项规则测试通过，其中新增测试覆盖空闲态返回 `null`，四种活动输入态返回真实塔种；Cocos Creator 3.8.8 Web Mobile 发布构建通过。
- 右侧浏览器 360×780、默认入口无 `qa=1`：点“开始布防”后，机枪卡只有教学指针、无操作描边，辅助描述为“未拿起炮塔”；点机枪卡后出现操作描边，描述改为“已拿起机枪塔”；点网格预览时描边仍在；同格确认后金币 140→110、机枪 0→1，描边消失，教学指针转到冷凝卡；跳过教学后不留教学指针或空闲态假选中。浏览器 error/warning 0。
- 同一浏览器前一轮保留的胜利结算页点击“重新部署”后，回到战前四塔、金币 10、路径 16、波次 0、累计生成/击毁/漏怪均 0、核心 10/10；这是作者浏览器复验，不是三局长测。

仍待至少 5 名无口头指导的首次玩家验证：箭头与描边的区别是否一眼可懂、误触是否减少，以及完整首局理解率。按当前要求不做 Android 真机测试。
