# 首关双列最小队距 review（2026-09-28）

## 为什么继续改规则

1312版只做有界视觉避让，密集减速区仍叠成团，未关闭方案§10.3的最小队距。
这轮把「前排停留时后排不能穿过」放回纯规则层，仍使用同一BFS与已承诺两格，不迁移引擎、不重写地图和经济。
game-ai用于分离路径/局部交通，physics-tuning用于固定步进与长帧限流；没有新物理引擎或刚体。

## 实现与边界

- `EnemyTrafficRules`：两列、同列沿共享有向路线至少0.7格，前排先推进、后排按剩余空间推进；不倒退、不积攒等待位移，不重新BFS。
- 格心交接、下一段和支路合流预留间隙；另一列前后窗口都足够才可超越。疾行者单独空场仍保持1.6倍步兵速度，没有统一降成重装速度。
- `waitingEnemyCount`表示本步被队距限制的单位，包含缓行和完全停等；`waitingEnemySeconds`是这些单位数乘时间，不能解读成整段完全静止时长。
- 入口两列均满时，未进场数量继续留在波表；不计作已生成/击杀，不提前清场，不积攒负倒计时爆刷。
- 长帧在规则内部按至多60个1/60秒子步推进生成/移动/射击，单次超过1秒明确拒绝；正式运行仍由统一`SimulationClock`提供固定步进。
- 首关装配默认双列；`enemyTraffic=legacy`仅用于旧移动对照，QA、图片档和朝向资源参数均不改变选择。换网格、战前恢复与重开继续传递同一交通配置。
- 规则快照给出列号；表现层侧向±0.23格，复用有界避让/模拟时间平滑、暂停冻结、尸影保持。双列不再用“同格即叠团”的旧人数徽标遮住身体。
- 战斗纯构造器不传交通配置仍保留旧规则，供明确基线fixture；新增真实双列测试/报告都显式传正式配置。不能拿旧fixture的32.95秒当当前普通首波。

**队距不是全局像素碰撞保证**：0.7格保证范围是共享有向路段的同列纵向间隔；异列、合流和转弯由局部交接处理。
不是所有Sprite像素/投影都互不重叠，也不等于任何未来地图都有无死锁证明。
