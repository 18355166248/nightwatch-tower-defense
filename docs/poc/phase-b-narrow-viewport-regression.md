# Phase B 第一关窄屏界面回归（2026-09-27）

## 问题与范围

第一关使用固定高度 1080×1920 设计坐标。右侧浏览器约 377×600 时可见宽度足够，但 360×780 长屏对应的可见设计宽度仅约 886，原 910 宽入场卡、970 宽顶栏以及两侧按钮会被裁切；底部帮助行还在屏幕底边溢出。这是首关实际操作问题，不是引擎迁移的依据。

本次保留 fixed-height，未缩小战场或改动寻路/经济/战斗。`PhaseBLayout` 统一从当前可见设计宽度计算左右 24 设计像素留白、四张资源卡和侧边按钮矩形；HUD、入场卡、程序化底板、触摸判定共用该布局，视窗尺寸变化时重新同步。底部帮助改为单行短句，操作说明仍由顶部状态和逐步引导承担。没有新增设备分支或改动玩家默认玩法。

## 验证

- `npm run verify`：68/68 通过；新增 360×780、390×844、430×932、1080×1920 四种视口的安全宽度与按钮热区几何断言。
- `npm run build:web`：Cocos Creator 3.8.8 Web Mobile 发布构建成功。
- 右侧浏览器实景：360×780 入场卡左右留白完整；布防界面标题、金币/路径/波次/核心、音效与底部操作均在画布内，底部帮助完整。390×844、430×932 和 1080×1920 检查了同一构建的顶部/底部布局；动态修改视口后状态仍保留。
- 360×780 上真实点击：开始布防成功；零塔点开波被“至少建造 2 座炮塔”门禁拒绝；速度 1×→2×；音效开→关；选机枪、预览接受、同格再次点击建造后 140→110 金、0→1 塔。浏览器 error/warning 0。

## 边界

浏览器视口验证不能证明 iOS 刘海/系统安全区、Android 导航区、物理触控尺寸或真机帧时间。首次玩家能否快速理解“两次点格子确认”仍需无引导样本；默认入口也尚未手动完成八波。按当前要求暂不做 Android 真机测试。页面：`http://127.0.0.1:4176/?build=phase-b-narrow-player-0945`。
