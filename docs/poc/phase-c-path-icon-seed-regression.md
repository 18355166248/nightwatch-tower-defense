# 路径长度 HUD 单图试点：切图、动态读数与浏览器回归

日期：2026-09-27。本轮只为首关顶栏第二个资源卡制作一枚路径图标候选；不将 HUD 合成方向稿作为运行时整图，也不改寻路、经济、波次或输入热区。

## 来源与迭代

- 通过 OpenAI 内置 `image_gen` 生成，输入仅为本项目已有金币/核心图标与本轮路径候选，供材质和轮廓迭代参考；没有输入《Fieldrunners 2》截图或素材。主提示词约束为：单枚透明的铜边深蓝路线 HUD 图标，青蓝路径与节点，左上暖光，方形居中，32×32 原生尺寸仍可辨，不含文字、数字、卡框、背景、Logo 和投影。第三版追加“紧凑 L 形拐弯、恰好三个节点、不要问号形轮廓”。这是本轮提示词的要点记录，不充作逐字原始调用日志。
- v1 在 32×32 下近似问号，v2 的横线在 128×128 方图中实际高度过小；两者只留在 `art-source/first-level-hud/` 供交叉评审，不进入运行时。v3 的 L 形占据图标高度，选作引擎内候选。
- 原图 `art-source/first-level-hud/path-route-source-v3.png` 为 1254×1254；以 `sips -Z 128` 和 `sips -Z 32` 分别得到 `path-route-128-v3.png`、`path-route-32-preview-v3.png`。128 版复制为 `assets/resources/level-one/ui/path-route.png`；`path-route-v3-manifest.json` 记录契约、来源与待审批状态。
- 此图为 AI 生成候选，不等于原创性、商业使用权或整套 HUD 方向获批。图标只说明“路径”，具体长度始终由动态文字给出，不能靠图案推断格数。

## 技术与浏览器回归

- 运行时 PNG：128×128 RGBA、18,508 B，alpha 0–255，内容边界 `(0,5)–(115,119)`；Cocos Creator 3.8.8 导入为 `sprite-frame`，已生成 `f9941` 子资源。
- `PhaseBHudView` 与金币、核心共用 `HudResourceIconView` 的异步加载和 `layoutResourceCard` 排版。路径图标加载成功时数值仍显示“12格”等单位，未就绪时退回完整“路径 12格”；没有新增寻路状态或单独输入逻辑。
- `npm run verify`：92/92；Web Mobile 发布构建和 `git diff --check` 通过。右侧浏览器 `http://127.0.0.1:4176/?build=phase-c-path-icon-final-1426`、约 390×600：进入默认教学见路径 12格；选择机枪并点 `(4,2)` 预览见 14格/金币 140；再点同格确认后见 14格、金币 110、机枪 1 座。图标及“格”未挤压相邻资源卡；控制台 error/warn 为空。

## 证据边界与交叉评审

- 这是最终路径图标构建的首塔检查，并非八波重跑；此前第 65 节完整八波证据属于不同构建。未取得 5 名无指导首次玩家的图标识别率/首关理解率，也没有正式音效与整套切图审定。
- 建议交叉评审重点：12–14px 实际显示下，L 形图标是否被理解为路径；“格”是否比仅有图标更清楚；青蓝路线图标和已有金币/核心图标是否属于同一套材质。若认可，再依同一资产契约扩展波次图标；若不认可，只替换装饰图，不影响动态数值及战斗规则。
- 按当前约定仅使用右侧浏览器，不做 Android 真机测试。Phase B/Phase C 不因该候选图标宣布通过。
