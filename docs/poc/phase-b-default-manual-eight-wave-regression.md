# Phase B 默认入口手动八波回归（2026-09-27）

## 验证边界

- 在 Cocos Web Mobile 发布构建的默认入口打开 `http://127.0.0.1:4176/?build=phase-b-manual-player-1004`，无 `qa=1`，360×780 浏览器视口。由项目作者按屏幕提示实际点击任务卡、塔卡、网格、升级和开波按钮；没有使用 `A/B/Space` QA 夹具，也没有调用游戏内部方法改状态。
- 开局为 140 金、0 塔、12 格路线、1×、核心 10/10。按教学布置 `(3,2)` 机枪、`(2,2)` 冷凝、`(4,2)` 与 `(5,2)` 机枪，金币变为 10、路线延长到 16 格。开第一波后切到 2×，每波清场手动点击继续。
- 此次是熟悉方案的作者沿推荐构筑操作，不是无指导首次玩家样本；2×、波间主动继续，不能用耗时证明 1× 的 6–8 分钟局长。只读 `data-phase-a-state` 用于核对统计，浏览器画面用于核对反馈。

## 对体验目标的判断

- 本轮补齐了之前缺失的“默认入口实际点选整局”工程证据；入场→四塔教学→预览/确认→战斗→波间升级/补塔→八波胜利可以闭环。结算重部署按钮在这轮为了保留胜利画面尚未再次点击；其既有工程回归见 `docs/poc/phase-b-result-loop-regression.md`。
- 当前结果证明推荐路径可玩，不证明玩家会自主想出构筑、理解冷凝收益或觉得中后段有趣；作者知道该点哪里，容易高估引导效果。需按总方案请至少 5 名新的首次玩家无口头指导试玩，保留每人原始观察记录。
- 目前画面仍是灰盒/候选素材：密集敌群主要靠 `×N` 徽标辨数，炮塔和敌人在 360 宽屏上偏小，胜利卡的信息层级清楚但视觉风格尚未达到正式切图水平。先用首次玩家数据修正理解与操作问题，再进入 Phase C 的批量美术；此轮不做 Android 真机测试。
