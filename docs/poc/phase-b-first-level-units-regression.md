# 第一关静态单位切图浏览器回归 · 2026-09-26

范围：原创机枪塔、冷凝塔、发条步兵三张静态透明图；只验证 Web Mobile 发布构建与右侧浏览器，不包含 Android/iOS 真机、动画或真人评审。

环境：Cocos Creator 3.8.8 Web Mobile 构建，`http://127.0.0.1:4176/?build=first-level-units-indicators-0037`，浏览器视窗约 377×600。`npm run verify` 29/29 通过。

| 操作 | 观察结果 |
|---|---|
| 默认进入第一关 | 两种塔的商店图标显示为独立切图，金币 120、路径 12 格；未显示 QA 入口 |
| 机枪塔预览 `(4,3)` | 半透明塔图与射程圈同格，预览路径 14 格 |
| 确认机枪塔、预览并确认冷凝塔 `(3,5)` | 金币 120→90→50，战场两种塔可辨识，路径保持 14 格 |
| 开始第一波 | 发条步兵切图沿改路移动；血条与减速圈跟随敌人显示在切图之上；击杀后金币增加，1×/2× 控件仍工作 |
| 核心归零 | 结算弹窗覆盖战场，单位 Sprite 不压在弹窗上；本次随意布置仅击毁 2/16、漏怪 10，不作为平衡结论 |
| 点击重新部署 | 恢复开战前两塔与金币 50；敌人节点消失，塔切图继续显示 |
| 浏览器控制台 | 0 error、0 warning |

资源导入注意：首次导入 PNG 被 Creator 标为普通 `texture`，需将三张 `*.png.meta` 的 `userData.type` 设为 `sprite-frame` 后重新构建，资源路径 `level-one/units/<id>/spriteFrame` 才可加载。运行时三个 SpriteFrame 全部就绪后统一显示；任一缺失时沿用 Graphics 灰盒。

结论：静态视觉样板已能支撑可玩的第一关战场，但密集敌人会重叠；还需要动作、炮身朝向、受击/死亡反馈、HUD 正式资产、音效和首次玩家观察。浏览器验证不代表移动端发布验收。
