## 实测与还原差异

`browser-layout-samples.json`记录三档实际CSS尺寸与操作。当前浏览器保留用户130%缩放，测试通过视口物理尺寸补偿达到实际CSS 320/390/430，不修改用户缩放设置。

| 实际CSS画面 | 结果 |
| --- | --- |
| 320×569 | 图像/文字契约加载正常，无横向滚动；主要可点击控制约44px；速度热区与下一波不重叠 |
| 390×693 | 三个主框位置与尺寸对照原稿，1080坐标换算最大偏差0.014px |
| 430×764 | 三个主框位置与尺寸对照原稿，1080坐标换算最大偏差0.014px |

0.014px是**框体几何对照**，不是整页像素差，也不是“99%还原率”或审美评分。文字复用原稿基线与字体，实际浏览器叠图未再看到初轮的明显文字重影；图标原生排布仍有约2设计像素的偏差，肖像边框/圆角也与原稿裸图不同。320宽为44px热区让下一波槽顺延约6CSS像素，固定原稿不表达这一适配差异；后续应将窄屏状态单独纳入设计批准。

首轮叠图后又提高了文字规格：320宽塔名/属性值约13px、资源大数字约16px；副文案约12px；禁用按钮/倍速说明约10.7px。仍有视觉风险：禁用出售/满级示例较矮，不能直接当可点击升级按钮规格。正式交互态需增大热区并重新评审，不能用全页无限缩放掩盖问题。当前不宣称这些状态具备正式交付品质。

真实操作覆盖：三个对照模式、320/390/430切换、两塔选中、关闭面板/机枪重新打开、1×→2×、暂停/恢复、切回对照时复位。当前页error/warn为空。JS语法、JSON解析、源图alpha通道和diff检查通过。

浏览器截图保留`browser-*-restored.jpg`、`browser-handoff.jpg`；截图后端在当前缩放下重采样，文件像素不等于CSS尺寸，几何判定以DOM实测为准。尝试1080导出时截图截掉右侧，另存`browser-export-cropped.jpg`诊断记录，**不作为1080还原稿交付**。完整设计PNG由SVG独立导出，不能拿它冒充浏览器还原截图。

## 字体修订（用户反馈后，覆盖前文旧字号）

用户指出字体比例不合适。直接测量发现SVG文字层本身已有等比缩放，但上轮逐项增大说明、属性及按钮字号，使字与面板失衡。本次所有文案与数值统一使用`baseSize × 0.86`，暂停/关闭操作符号保留原尺寸；移除Arial优先级，原稿与原生文字统一使用`PingFang SC / Microsoft YaHei / sans-serif`家族。声明字体家族不等于已固定跨平台字体文件，本轮没有引入新字体授权资产。

字体随战场`viewBox`一次缩放，不设置最小字号来抵消缩小；点击热区仍独立保留约44px。参考稿SVG/PNG和`typography.json`同步再导出，避免只改页面导致叠图字号不一致。

实测记录为`font-scaling-samples.json`：320→390实际宽倍率1.21873，320→430倍率1.34375；29个文字节点的屏幕字宽倍率与画面宽倍率最大差值小于0.001（栅格取整误差）。这是同比缩放证据，不是审美达标证据。修正后的实际默认浏览器截图为`browser-font-refined.jpg`，保留先前截图用于追溯，不把旧截图当最新字体效果。

当前390宽名义字号：资源数字约17px、选塔标题约14.3px、塔栏名称约13.7px、副说明约12.4px、按钮说明约11.2px；320宽对应继续同比缩小。窄屏可读性仍需用户判断，后续如需更大字体，应通过专门窄屏排版调整，而不是单独放大文字破坏同稿比例。当前未接入Cocos、未提交。
