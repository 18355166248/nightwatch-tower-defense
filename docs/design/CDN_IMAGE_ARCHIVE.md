# 设计与历史图片 CDN 归档

本次仅归档 `art-source/` 和 `docs/` 下的 PNG/JPEG，以及设计 SVG、动画预览 HTML 内嵌位图。`assets/resources/` 全部保留本地，不改变运行贴图、游戏包体积或游戏联网依赖。

清单：`art-source/cdn-image-manifest.json`。每个历史路径对应原图 URL、原图 SHA-256/字节数、预览 URL、预览 SHA-256/字节数及下载校验时间。同内容图片去重上传。原始字节单独归档以保留切图来源；大于等于 64 KiB 的图片另尝试 TinyPNG 压缩预览，小图使用原字节。压缩服务失败会报告并保留原图 CDN，不购买额度。

CDN 为用户明确授权的 `https://audiopaytest.cos.tx.xmcdn.com`。本次实际下载校验成功不代表永久留存保证。游戏本身不受 CDN 可用性影响；设计评审和源图恢复需要联网。

## 评审与重新切图

- 设计 HTML/CSS/Markdown 中可解析的图片引用已改成 CDN；状态索引和来源 JSON 保留历史路径作为来源标识。
- `node scripts/serve-design-review.cjs` 可继续处理这些历史图片路径，返回 CDN 重定向。SVG 在 `<img>` 场景下不允许远程子图，因此预览服务会验证原图后临时内嵌到响应，不重新落盘。
- 当前 v3 切图／对照脚本使用 `scripts/design-image-store.cjs`，本地缺图时下载原图并核验 SHA-256，失败即报错，不使用压缩预览替代原图。
- 旧批次导出脚本仍按历史路径工作，先运行 `node scripts/restore-design-images.cjs art-source/具体目录`（或 `docs/design/具体目录`）恢复所需源图，再运行旧脚本。此命令显式限定范围，不覆盖已有文件。
- 恢复或新生成评审图片后，需要重新执行上传与收尾流程，不能将图片重新加入 Git。

## 迁移命令

在项目根目录配置 `IMAGE_UPLOAD_SKILL` 为本机 `xmly-upload-image` 技能路径，使用 Bun 执行 `scripts/archive-design-images.ts`，再运行 `node scripts/finalize-design-image-archive.cjs`。上传阶段不删除；收尾阶段检查完整覆盖、本地原图哈希与验证记录后，只删除清单内的图片。

上传配置、技能凭据和临时压缩图不进入 Git。离线测试核对来源契约和本地运行 PNG；在线下载校验与离线测试分别记录。

## Git 与恢复边界

本阶段大图片从新提交移除，上一阶段提交已按授权软撤回。更早历史及撤回提交的对象可能仍占用 `.git`，本次不清除 reflog、不重写更早提交、不推送。删除的工作区图片可按归档清单恢复；原图 CDN 与压缩预览分离。
