## 视觉与技术框架

- 设计基准 1080×1920；浏览器按完整 9:16 画面缩放，320/390/430 宽检查；预览外层评审说明不属于游戏 HUD。
- 常规较矮桌面侧栏会按可见高度整体收敛预览，顶部实时显示真实画面尺寸；三档正式小屏检查使用上述实际视口，源稿导出不使用高度收敛。
- 正上方略带 2.5D 体积感。黄铜与深蓝珐琅，蓝紫石板、青蓝控制、琥珀奖励、绿色合法/主确认、红色危险。
- 近似色板：地面 `#646781`、阴影 `#242938`、深蓝钢 `#192C3B`、黄铜 `#BE8F48`、暖光 `#FFCB75`、控制 `#64DCE3`、合法 `#75D799`、危险 `#DE6A58`、主文字 `#F4E9CD`。生成画面允许材质变化；HUD 采用确定色值。
- 关键文字至少 36 设计像素（390 宽约 13 px）；主价格/生命 52–62 像素；次要文字 30–32 像素；320 宽须检查而非无限缩字号。
- 常用触控按实际尺寸至少 44×44 CSS px 的目标设计；棋盘保留现有小格点选/预览机制，44 px 不作为每格已满足的声明。
- 底部工具栏只保留两塔与战斗控制，选塔时叠加紧凑属性面板；范围圈低不透明度，不用大光斑盖住单位。
- 文字、数值、点击区域、射程圈、路线与状态由独立原生节点承担。代表画面中的场景/塔/敌人/特效合成层仅作视觉目标，不能直接作为游戏资产或正式切图源。
- 后续运行时预算仍为首屏传输 ≤3 MiB、常驻纹理目标 ≤8 MiB、H5 总包 ≤20 MiB；不以磁盘压缩或放宽门槛代替验证。当前旧构建总 GFX 11,668,588 B 的失败记录保留。
