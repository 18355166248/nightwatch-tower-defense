# 第三关与战役扩展实施规格

版本：v1.11；确认日期：2026-10-07；当前阶段：第三关、正式素材、阵容与建造／升级环已接入，浏览器验收与交互收口进行中。

本文件是本轮需求的唯一实施依据；进度与验收证据见 [进度追踪](THIRD-LEVEL-PROGRESS.md)。历史首关试验、参考游戏截图和代码中的旧双塔分支不能覆盖本规格。基线提交为 `eda35d2`。

## 1. 已确认的目标与边界

- 新增第三关“钢铁堡垒”，新兵种为护甲坦克、护盾兵，新炮塔为穿甲炮、电弧塔。
- 克制明显但不完全免疫；前两波认识新机制，后六波混编高压。
- 每局先配置出战塔，最多 5 种；本次第三关提供 4 种，不为填满第五位置额外增加塔。
- 第一、第二关固定携带原有机枪、冷凝；第三关允许选择 1–4 种，默认全选四种。
- 建塔采用围绕落点的紧凑等分圆弧选塔，不设关闭按钮，点击图标外空白收起；升级保留三级圆环。
- 三关分别使用独立战场背景，不能仅换颜色；继续使用 9×13 棋盘和中央第 5 列出入口。
- 保留自由建塔改路、战斗中建塔、三级升级、暂停、出售与重开流程。
- 不加入坦克反击、护盾保护队友、炮塔耐久、维修、飞行兵、联网或额外关卡。
- 默认不自动提交、不推送；代码提交等待用户明确指令。

## 3. 出战选塔与关卡流程

流程：欢迎页 → 关卡地图 → 独立配塔页 → 布防 → 开始战斗 → 结算。

- 配塔页显示本关敌情、炮塔图片、用途与克制提示，以及“已选 N/5”。
- 前两关展示配塔页，但原两塔固定携带并解释新手配置；不开放新塔回打前两关。
- 第三关允许选择 1–4 种；零选择不能进入，第六种不能加入，重复 ID 不占槽。
- 未带穿甲或电弧时提示本关坦克／护盾风险，允许继续，不强制指定构筑。
- 塔的选择顺序作为棋盘建造菜单顺序。默认顺序：机枪、冷凝、穿甲、电弧；局内底部不再展示塔列表。
- 本局进入布防后锁定阵容；重新部署沿用本局阵容，返回配塔页才能换塔。
- 按关卡保存上次阵容。使用独立、带版本的本地存储，不复用成绩键；首次访问、坏数据、未知或不允许的 ID 回退到关卡默认阵容。
- 第二关胜利增加“挑战第三关”，经过第三关配塔页；地图直接展示第三据点，不新增通关解锁门槛。
- 第三关最快时间、最佳核心和重开记录独立于前两关。

### 4.2 结算契约

- 敌人配置增加可选护甲、最大护盾；运行时增加当前护盾。旧敌人缺省为零，前两关旧结果保持一致。
- 炮塔配置增加护甲穿透、对盾倍率和索敌优先级。穿甲炮各级忽略 90% 护甲，其余塔缺省不穿甲。
- 生命伤害 = 剩余攻击量 × (1 − 护甲减伤率 × (1 − 护甲穿透率))。
- 护盾优先吸收；对盾倍率为机枪 0.6、穿甲 0.6、电弧 2.5、冷凝 1。护盾伤害不再受护甲减免。
- 护盾被击破时，剩余攻击量 = 原攻击量 − 被消耗护盾值 / 对盾倍率，再按护甲规则结算生命；不得把破盾倍率带入生命伤害。
- 护盾破坏不是击杀；击杀、赏金、死亡动画与统计只结算一次。
- 新塔都是单体伤害，不额外加入连锁或爆炸群伤。冷凝减速独立结算，继续采用强效果覆盖、持续时间刷新，不叠乘冻结。
- 穿甲优先有护甲目标，电弧优先仍有盾的目标；同类按距出口排序，没有克制对象时攻击普通目标。
- 目标失盾、死亡或离开射程时重新判定；锁定不能使电弧持续忽略其他有盾目标。机枪／冷凝沿用原优先级。
- 射击事件区分实际护盾伤害、生命伤害及破盾事件；伤害数字、反馈与统计不得把盾伤当生命损失或漏怪。

## 5. 紧凑等分圆弧选塔

2026-10-07 用户最新反馈覆盖单行／双行排列：取消落点与浮层的大间距，多塔围绕中央选中圈，并等分圆弧。保留无关闭按钮及空白收起。

- 所有选项统一60×60圆形图标（v1.7从52放大约15%），图标和价格样式一致；单塔一个节点，多个塔围绕落点完整等分圆周。
- 半径按中央选中圈及选项尺寸计算，选项边缘贴近中央圈，不再预留上下左右整行格子产生的大间距。
- 始终以真实塔位／选中落点为圆心，边缘也不平移、旋转或改变排列。两按钮固定上下排列；三按钮120°等分；四按钮90°等分形成整齐的四角；五按钮72°等分。禁止边缘压成扇形。图标、价牌之间保留间隔；弹窗显示层级和图标命中优先级最高，可以覆盖HUD和其他场景元素；说明卡仅限制屏幕边界并避开弹窗图标。
- 不增加关闭按钮或占位。不绘制中心连线、菜单外圈或重复选中圆线；按钮保留自身边框和真实价格。中心和其他空白点击收起，不扣费。
- HUD动作优先接收，开波／速度不被空白关闭吞掉，自动开波仍保留菜单。
- 建造长按／悬停说明、禁用原因和提交重读沿用真实事务；原保留四邻格全部空白的布局约束被最新紧凑圆环要求覆盖。
- 升级机制、底部控制和战斗数值不变；150毫秒动效及真机触摸继续独立验收。

### 5.1 塔升级环、悬浮信息与亮点

用户第二张截图作为升级交互参考：塔位居中，射程圈可见，外围圆形升级节点带图标和价格，节点边缘的升级圆点逐级亮起，下方单独放置出售入口。

已确认纳入本轮：

- 选中已建塔时，显示射程并展开升级环，与建造环共享铜框、展开动效和边缘避让风格。
- 塔上方提供名称、当前等级和用途／克制的悬浮信息；只在选中或查看该塔时展开完整说明，不默认给全场塔常驻大段文字。
- 升级图标旁的说明包含当前效果、下一次提升及价格；保留当前／下一等级真实塔外观预览，不能只换名称。
- 升级圆点表达已购买进度：只有成功购买后点亮；金币足够时升级按钮亮起／高亮，不能把“买得起”误显示成“已升级”。
- 尚未购买的点为暗色；满级显示已满级，不再显示可购买价格。高亮以颜色与形状区分，降低动态效果时仍清晰。
- 购买提交时重读金币、当前等级和局内阶段；失败不扣费、不点亮、不改变塔外观。出售入口显示当前阶段真实返金，沿用已有比例。
- 暂停、切关、重开、出售、后台与异步素材回调不能留下旧塔的说明、亮点或射程；升级面板不遮挡相邻格换选。

**已确认 U01：保留三级线性升级。** 用户明确选择“保留现有三级升级，购买后点亮等级圆点”。一级初始点亮，二／三级随实际购买点亮；只显示真实的下一次升级、出售及收起，不新增独立技能分支，不虚构多个技能按钮。

## 7. 实现与验收要求

- 关卡增加背景与允许塔目录；独立出战阵容统一驱动棋盘购买菜单、图标、升级与战斗。不让多个 UI 私自维护塔名单；底部战况控制与塔目录解耦。
- 集中实现伤害结算；清理“非冷凝就是机枪”的名称、素材、攻击与升级分支，按目录处理四种塔。
- 无机枪阵容以首个携带塔为默认选择；格子预校验不能仍固定调用机枪。未携带塔不可通过旧输入、QA 以外的旧路径或悬停状态购买。
- 暂停、后台、重开和切关正确处理阵容、护盾、目标锁、预览与异步素材。关键状态／兼容／回退逻辑补充中文注释。
- 售塔比例沿用现有战前全退、战斗五折、波间七折规则；升级不丢穿甲／破盾属性。
- 自动化覆盖减伤、盾伤溢出、重复击杀、减速、优先级切换、阵容上限与过滤、跨波菜单、边缘换格、异步背景迟到和资源降级。
- 用测试用塔目录覆盖 5 种与超过 5 种，不为测试上限向正式游戏硬加第五塔。
- 前两关固定阵容回放结果保持一致；第三关至少记录一套可通关混合构筑，与同预算缺穿甲／缺电弧构筑的分兵种伤害、漏怪和核心生命对照。
- 通过规则、类型、美术与发布构建检查，再完成浏览器配塔至结算全流程、1×／2×、上下换格、重开与背景切换。
- 手机触摸、后台、帧率、内存预算、三局连续运行和真人视觉／难度验收分别记录，不拿桌面浏览器证据替代。

## 8. 防漂移与变更规则

1. 每个任务使用进度表中的固定 ID；开始写代码前读本文件和当前进度。
2. 先更新状态为“进行中”，完成时补具体文件、命令／日志、截图及剩余验收；没有证据不标“已验收”。
3. 数值可在回放阶段调整，但须保留原值、原因、结果，并同步本规格版本与变更日志。
4. 背景独立、环形菜单、最多五种出战塔、前两关固定双塔、无完全免疫等产品约束不能自行改掉；冲突先与用户确认。
5. 新用户要求同时更新规格和进度，不只写在聊天里；旧记录注明“被哪一版本替代”，不删除历史证据。
6. 遇到资源或平台阻塞，只标相应任务和原因，继续无依赖任务；不能悄悄删掉功能或把降级占位标成正式完成。
